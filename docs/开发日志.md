### 11:50 | 阶段0：需求确认与技术方案

- **需求**：批量视频拖入 → 自动转写口播字幕 → 违禁词检索 → 标注"哪个视频第几秒说了什么" → 一键定位播放。

- **技术选型决策**：

  - 字幕识别：**faster-whisper（本地 GPU）**，放弃剪映工程文件方案（无批量接口、草稿格式随版本变动、自动化脆弱）。

  - 存储：**SQLite**（零部署、单文件、支持历史留存与"换词库免重转写"重新检索）。

  - 视频定位：前端 `<video>` 标签 + 后端流式播放（支持 Range），不依赖外部播放器。

- **用户约束**：

  1. 所有下载/安装文件必须收在 `E:\AI制作程序\违禁词检测` 项目目录内，保持整洁有序。
  2. 每一步操作记录到开发日志（本文档）。
  3. VPN 已连接，需要访问 GitHub/HuggingFace 时优先走 VPN。

### 12:40 | 阶段4：网络问题排查（模型下载）与解决

模型下载遇到障碍，排查过程与结论（重要，供后续环境问题参考）：

| 测试项                                     | 结果                                        |
| --------------------------------------- | ----------------------------------------- |
| huggingface.co 直连                       | 超时不通                                      |
| huggingface.co 走 VPN 代理(127.0.0.1:7897) | 超时不通                                      |
| hf-mirror.com 直连                        | ✅ 通（0.4s）                                 |
| hf-mirror.com 走 VPN 代理                  | ❌ TLS 握手被劫持（EOF in violation of protocol） |
| 同代理访问 github.com                        | ✅ 正常（VPN 本身可用）                            |

**根因**：

1. Python httpx 通过 `urllib.request.getproxies()` 自动读取 Windows 系统代理 → 走 VPN 访问 hf-mirror 被 TLS 劫持；
2. huggingface\_hub 1.29 + hf-xet 1.6 默认走 Xet 协议，hf-mirror 不支持 → 直连也卡死在 0 字节；
3. 绕过 Xet 后直连 hf-mirror 可用，但该模型实际重定向到 HF 美国 CDN（us.aws.cdn.hf.co），直连仅 \~165KB/s（3GB 需 5 小时，不可接受）。

**解决方案**：

- 发现 **ModelScope（阿里魔搭）官方镜像了 Systran/faster-whisper-large-v3**（同源同文件，CTranslate2 格式），国内直连实测 **5.7MB/s**；

- 编写 `tests/download_model.py`：优先 ModelScope（断点续传 + 重试），回退 hf-mirror；模型落到 `data/models/local/<name>/`；

- `transcriber.py` 增加 `_resolve_model_path()`：**优先加载本地模型目录，完全离线可用**；

- `_setup_hf_endpoint()`：endpoint 为 hf-mirror 时自动绕过系统代理直连（已验证必要）。

**对产品的影响**：用户首次使用前需运行一次 `tests/download_model.py`（或手动放置模型文件到 `data/models/local/large-v3/`），之后永久离线。

### 14:15 | 阶段10：修复"浏览文件"导致服务崩溃（Failed to fetch）

**现象**：用户点击"浏览文件"后页面报 `Failed to fetch`，服务进程直接死亡。

**根因（Windows 事件日志 0xC0000005）**：

```
出错应用程序：python.exe
出错模块：wetype_tip.dll_unloaded（版本 2.1.1.6）   ← Windows 中文输入法/文本输入平台组件
异常代码：0xc0000005（访问冲突）  时间：14:02:56
```

tkinter 弹出系统文件对话框时，系统输入法组件（wetype\_tip.dll）注入进程并访问已卸载内存 → **访问冲突使整个 FastAPI 进程死亡**（进程级崩溃，无法用 try/except 捕获）。

**修复**：把 tkinter 选择器改到**独立子进程**运行（`app/server/api.py` 的 `/api/pick`）：

- `subprocess.run([sys.executable, "-c", _PICK_HELPER, mode, ...])` 弹窗；

- 即使输入法组件再崩溃，也只死子进程——**主服务进程绝不受影响**，用户重试即可；

- 子进程以 JSON 输出所选路径；退出码非 0 / 输出不可解析 → 返回明确错误提示，不再是无信号的"断连"；

- 保留 600s 超时（超时→504 提示），沿用 CREATE\_NO\_WINDOW 隐藏黑窗。

**效果**：崩溃从"服务整体宕机"降级为"单次选择失败可重试"，前端不再出现网络层 `Failed to fetch`。

**待办**：若后续子进程仍被该 DLL 干扰频繁崩溃，备选方案是改用 PowerShell WinForms（`System.Windows.Forms.OpenFileDialog`）作为选择器，与本方案互斥不叠加。

## 2026-09-05（v1.2.0 发布后：真机反馈问题集中修复）

> 在英伟达/AMD 真机试用后暴露一批问题，逐一定位修复，并重新打包。

### 1) 模型文件集错误（核心：导致转写失败）
- 用 ModelScope 仓库文件 API 确认：**不同模型词表文件不同**——`large-v3` 用 `vocabulary.json`，`medium/small/base/tiny` 用 **`vocabulary.txt`**；且 `small/medium` 还缺 `preprocessor_config.json`。
- 旧代码把 `vocabulary.json` 写死为所有模型必需 → 下载 small/medium 时一直去拿不存在的 `vocabulary.json`（404 卡住）、漏掉 `vocabulary.txt`；且就绪判定只看 `model.bin/config.json/tokenizer.json`，导致**缺词表仍被误判可用** → 加载即报 `Cannot load the vocabulary from the model directory` → 转写全部失败。
- 修复：`MODEL_FILES` 候选清单加入 `vocabulary.txt`、`configuration.json`；下载按「源上实际存在」挑选；`is_model_ready` 改为「3 核心 + 至少一个词表文件」；`_MODEL_FILES_EXPECTED` 按模型精确展示。
- 实测：`small` 补上 `vocabulary.txt` 后加载成功；`种草视频.mp4`（之前必失败的视频）转写成功。

### 2) 下载进度恒 0 / 卡 0%
- 前一轮把下载状态从 `frac` 改成 `overall`，但顶栏与「当前引擎状态」仍读 `dl.frac`（不存在）→ 恒 0。
- 修复：状态同时带 `overall` 与 `frac`，前端 `overall ?? frac`；文案体积动态化（不再误写「约3GB」）。

### 3) 「多源竞速」测速不准 + 卡启动
- 旧 `_probe_speed` 用 2370 字节的 `config.json` 测速，只反映连接延迟（虚低 0.01MB/s），且会先下载 16MB 才真正开始，期间无进度。
- 修复：`_pick_sources` 改为「ModelScope 国内直连优先 → hf-mirror 备份」直接尝试（去掉下载式测速），下载即刻开始、进度可见；删除 `_probe_speed` 死代码。

### 4) 就绪判定过松（已并入 1）
### 5) 加载失败误切镜像
- `_load_model_once` 之前对**任何**加载异常都切 hf-mirror 重试（本地模型加载失败如词表错也切，毫无意义且误导日志）。
- 修复：仅当 `model_name` 非本地路径（确需在线下载）时才切换镜像；本地加载失败直接抛真实错误。

### 6) 无音轨视频优雅降级
- `media.has_audio_stream()`：无音轨 → transcribe 返回 `[]`，界面显示「未识别到语音内容」，不再「音轨解析失败」。实测 `短剧情_batch.mp4` 正确返回 0 段。

### 7) 英伟达机器转写卡死 + Failed to fetch（重要）
- 现象：模型 `large-v3 GPU int8_float16` 已加载，3 个视频「转写中」进度 0，前端 `Failed to fetch`，GPU 70% 占用。
- 根因：用户把并发数设为 3，**多任务同时对同一模型实例做原生推理**，`faster-whisper/ctranslate2` 发生**原生崩溃（段错误）**，try/except 捕不住，直接带崩整个服务进程 → 前端断连。
- 修复：`WhisperEngine` 增加**全局转写互斥锁 `_transcribe_lock`**，同一时间只允许一个视频做原生推理（其它排队）；并加「开始转写：路径/时长/设备」日志便于定位。
- 回归：互斥锁下 e2e（干净库）仍全部通过。

### 8) 在线更新方案调研（未实现，待确认）
- 需求：无网站/后台的在线更新。调研结论：
  - **GitHub Releases**（免费、单文件≤2GB、2025-06 起 API 提供资产 SHA256 digest）为推荐权威源。

  - **Gitee 发行版不可行**：免费单文件约 100MB 上限，包 149MB 超限。
  - 方案：GitHub 权威源 + 内置「直连→ghproxy 镜像清单」自动回退 + **SHA256 严格校验** + 可选 R2 国内优先通路。
  - **待用户确认**：GitHub 账号/仓库、是否接受 ghproxy 镜像、更新触发方式（静默+手动按钮）。尚未实现。

## 2026-09-07（v1.3.0：详细日志模式）

> 需求：把软件所有运行日志记录到软件根目录文件夹，尽可能详细，便于排查/定位问题根源。

### 实现内容
1. **统一日志目录**：软件根目录 `logs/` —— `logs/app.log`（Python 服务端）+ `logs/launcher.log`（C# 启动器），废弃原 `data/app.log`。
2. **日志格式**：`毫秒时间戳 | 级别 | 线程名 | 模块.函数:行号 | 消息`（MainThread / whisper-worker-N / AnyIO worker 一眼可辨）；RotatingFileHandler **20MB × 10 份**。
3. **记录范围（尽量详细）**：
   - 启动横幅：版本 / Python / 系统 / 根目录 / 数据·模型·日志路径 / 磁盘 / 显卡判定 / 系统门槛 / 当前设置；
   - 未捕获异常：`sys.excepthook` + `threading.excepthook` + warnings 全捕获；
   - HTTP：FastAPI 中间件（方法/路径/状态码/耗时）+ uvicorn access 全量访问日志；
   - 前端：`window.onerror` / `unhandledrejection` 自动上报 `/api/log`（sendBeacon），`api()` 请求失败也记录；
   - 转写：CUDA 检测/降级链/模型加载耗时/互斥锁等待/whisper 元信息/段数/耗时与倍速/ffmpeg 抽轨兜底；
   - 模型下载：源探测/每文件开始与完成/速度/重试/断点续传；
   - 去词：完整 ffmpeg 命令行（可直接复现）、探测参数、进度、退出码与 stderr、备份路径；
   - 任务/去词/词库检测/导出/数据库/设置 全生命周期。
4. **「详细日志模式」(DEBUG) 开关**：设置页新增「日志与排障」面板 → checkbox 写入 `settings.json` 的 `log_level`（info/debug），保存后**实时生效**。
5. **日志查看**：设置页「查看最近日志」（`GET /api/logs/tail` 最近 400 行，前端 `<pre id=logView>` 展示）、「打开日志目录」（`POST /api/logs/open`，`os.startfile`）。
6. **C# 启动器**：新增 `AppLog` 写 `logs\launcher.log`；记录启动（版本/PID/OS/.NET/exeDir）、服务启动与 PID、残留进程清理、服务退出（优雅/强杀）、WebView2 初始化、导航端口、原生拖放提交；挂 `AppDomain.UnhandledException` + `Application.ThreadException` 记录未处理异常。

### 关键决策
- `uvicorn.run(log_config=None, access_log=True)`：uvicorn 日志汇入根 logger，格式统一、全部落盘。
- httpx/httpcore/urllib3 降为 WARNING 防刷屏；`syscheck` 显卡/门槛日志改为 DEBUG（启动横幅已记一次 INFO，避免 /api/status 轮询刷屏）。
- `config.py` 新增 `LOGS_DIR`（=`BASE_DIR / "logs"`，打包后即软件根目录），`ensure_dirs()` 自动创建；`.gitignore` 增 `/logs/`。
- `GET /api/settings` 额外返回 `log_dir` 供界面显示；前端日志上报用 sendBeacon，页面关闭也能送达。
- 版本号三处同步：`config.py` / `Launcher.cs`(Ver+Program_Ver) / README → v1.3.0。

### 验证
- `py_compile` 全部通过；`node --check app.js` 通过。
- AMD 真机冒烟：启动横幅齐全；/api/status 与 /api/settings（含 log_dir）正常；POST /api/log 写入 `frontend.client_log`；/api/logs/tail 返回日志；log_level debug↔info 实时切换并落盘。
