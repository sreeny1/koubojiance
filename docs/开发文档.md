# 口播违禁词检测 · 开发文档

> 面向后续接手维护者：架构、数据模型、接口清单、关键设计、构建与分发、故障排查。

## 1. 系统概览

```
┌──────────────────────────────────────────────────────────┐
│ 口播违禁词检测.exe（C# WinForms + WebView2 桌面外壳）       │
│  · 内嵌网页界面  · 原生拖放(真实路径/零复制)  · 托盘常驻      │
└───────────────┬──────────────────────────────────────────┘
                │ 启动 python app/main.py --no-browser（本地 127.0.0.1）
┌───────────────▼──────────────────────────────────────────┐
│ Python FastAPI 服务（app/main.py）                         │
│  ├─ server/api.py       REST 路由                          │
│  ├─ server/tasks.py     转写任务队列（worker 线程）          │
│  ├─ server/cut_tasks.py 去词任务队列（worker 线程）          │
│  └─ core/*              业务核心                            │
└───────────────┬──────────────────────────────────────────┘
                │ SQLite（WAL）＋ 本地文件（data/）
```

前端为原生 JS 单页（`app/web/`），无框架依赖；与后端通过 `/api/*` JSON 交互，任务进度靠轮询。

## 3. 数据模型（SQLite）

- `meta(key,value)`：schema_version
- `videos(id, path UNIQUE, filename, duration_ms, created_at, transcribed_at)`
- `tasks(id, video_id, status, error, created_at, finished_at)` — status: queued/running/done/error/canceled
- `segments(id, video_id, idx, start_ms, end_ms, text)` — 字幕句
- `categories(id, name UNIQUE, color)` / `words(id, category_id, word, note, enabled)`
- `hits(id, video_id, segment_id, word_id, word_text, matched_text, start_ms, end_ms, sentence)`
- `cut_jobs(id, video_id, hit_ids JSON, pad, status, error, progress, backup_path, created_at, finished_at)`

外键 `ON DELETE CASCADE`；`Database` 用 `RLock` + 单一连接 + `check_same_thread=False` 保证多线程安全。

## 4. 关键设计

### 4.1 违禁词检测（双层匹配）
1. **归一化精确层**：`NFKC` 归一（全角→半角）→ 繁转简 → 小写 → 丢弃标点/空白 → 子串匹配，抓"第 一 名"等规避写法。
2. **拼音谐音层**：字级 `pypinyin` 无声调 token 序列匹配，抓"蕞好→最好"等谐音。

命中后通过 `normalize()` 返回的**位置映射表**反查原文片段；时间点按字符位置在字幕段内**线性内插**。

### 4.2 转写稳定性
- 模型加载降级链：`cuda+请求精度 → cuda+int8_float16 → cuda+int8 → cpu+int8`。
- **转写全局互斥锁 `_transcribe_lock`**：同一时间只允许一个视频做原生推理（其它排队）。ctranslate2/更快-whispers 并发对同一模型实例推理可能**原生崩溃**（try/except 捕不住、会带崩整个服务进程 → 前端 `Failed to fetch`），串行化是稳妥保障。
- 模型下载：以 **ModelScope 仓库文件 API 清单**（文件名/大小/SHA256）为契约下载并按清单复核对齐（large-v3→`vocabulary.json`；small/medium→`vocabulary.txt`），断点续传 + 每文件 SHA256 校验；ModelScope 直连优先、hf-mirror 备份；清单落盘 `data/runtime/manifests/<model>.json`。
- 就绪判定：3 核心文件（model.bin/config.json/tokenizer.json）+ 至少一个词表文件齐全；若有本地清单再按清单逐文件核对存在+大小。
- 首启环境自举（v1.4.0）：检测 NVIDIA 显卡（注册表）时先自动下载 CUDA 运行库（`cuda_setup.py`：清华→阿里→腾讯 PyPI 镜像解析 wheel+官方 SHA256 → 断点续传 → 校验 → 解压 data/runtime/nvidia → 11 个关键 DLL 核对），再下载模型；AMD/Intel 仅下模型。CUDA 失败自动降级 CPU。
- onnxruntime.dll 预加载（防 System32 被劫持，错误 1114）；nvidia CUDA DLL 从 `.venv` 或 `data/runtime/nvidia` 注册。
- 无音轨视频（`has_audio_stream` 为 False）直接视为「无语音内容」返回空字幕，不报错。
- 转写后超长字幕段按标点二次切分（`split_oversized_segments`）。

### 4.3 去词切割（ffmpeg）
- `probe_media()`（PyAV）取原片分辨率/帧率/像素格式/编码/音频采样率/声道/码率。
- 命中区间 + 前后 0.3s 缓冲 → 合并重叠 → 反推保留区间 → `trim/atrim + concat` 精确拼接。
- 重编码匹配原参数（h264/hevc + aac），`-movflags +faststart`；失败/取消删临时文件。
- 流程：备份原文件（同目录时间戳后缀）→ 输出临时文件 → `os.replace` 覆盖原名 → 清空陈旧字幕/命中 → 自动重新入队转写。

### 4.4 桌面拖放（零复制）
前端 `dragenter` → `postMessage("native-drag-enter")` → C# 显示全窗覆盖层 → WinForms 取 `FileDrop` 真实路径 → POST `/api/scan` → `PostWebMessageAsJson` 通知前端刷新。支持**多文件+多文件夹混合**；守护定时器兜底"拖出/松开"时覆盖层残留。

### 4.5 多显卡兼容
- NVIDIA → CUDA 加速；AMD/Intel/无独显 → CPU int8。
- `/api/status` 下发 `system.gpu`，前端明确提示"检测到 AMD 显卡，将使用 CPU 模式"。

### 4.6 最低配置门槛
启动器（C#）在启动服务前检查：内存 ≥ 8GB、磁盘 ≥ 8GB、CPU 支持 AVX2；不满足弹窗退出。Python 侧 `syscheck` 同步提供信息给状态接口。

### 4.7 在线更新（v1.7.0）
- 仓库根目录 `latest.json` 是版本清单；更新包发布到 GitHub Releases。
- 首版只更新 `app/` 目录（源码 + 网页），不覆盖 `data/`、`logs/`、模型、视频、Python 运行时和 exe。
- 流程：检查 `latest.json` → 比较版本 → 下载 zip（断点续传 + SHA256）→ 写 `data/updates/pending.json` → 用户点击安装 → 生成 PowerShell 辅助脚本 → 服务退出 → 脚本等待 PID 退出、杀项目目录内残留进程、解压覆盖 `app/`、重启 exe/bat。
- 兜底：下次启动时 `main.py` 最早阶段调用 `apply_pending_update()`，即使辅助脚本未执行成功也会覆盖 `app/`。
- 国内镜像：直连 GitHub 优先，失败时按设置尝试 `ghproxy.com` / `mirror.ghproxy.com` 前缀。
- 发布脚本：`scripts/make_app_update.ps1` 生成 app 小包；`scripts/publish_update.ps1` 同步版本号、写 `latest.json`，`-Publish` 时推送并调用 `gh release create`。

## 6. 构建与分发

```
# 1) 拉取 WebView2 依赖（幂等）
powershell -File scripts\fetch_webview2.ps1
# 2) 编译 C# 启动器
powershell -File scripts\build_launcher.ps1
# 3) 打包（自动排除 nvidia* 与 data/runtime——CUDA/模型首启下载，zip≈150MB）
powershell -File scripts\pack_full.ps1
# 3) 绿色免安装包（排除模型，首启自动下载）
powershell -File scripts\pack_full.ps1
```

- 打包脚本自动探测当前 `.venv` 的 Python base prefix，拷贝便携运行时 + site-packages。
- 模型（3GB）不进包；ffmpeg 经 imageio-ffmpeg 打进依赖（约 90MB，为可靠性保留）。
- 若需接收方支持 NVIDIA，请在**装了完整依赖（含 nvidia-cublas-cu12 / nvidia-cudnn-cu12）的机器**上打包。

## 7. 常见故障排查

| 现象 | 排查 |
|---|---|
| 页面打不开 / 端口漂移 | 残留 python 进程占 8765；用启动器统一管理，或看 `Get-Process python` |
| 模型下载失败 | 看界面「手动下载引导」；确认网络能直连 ModelScope/hf-mirror |
| 转写报 DLL 初始化失败(1114) | onnxruntime 被 System32 劫持，已做预加载；仍失败则重装 onnxruntime==1.19.2 |
| AMD 机器无 GPU 加速 | 正常：ctranslate2 Windows 无 ROCm 后端，走 CPU int8 |
| 中文路径乱码 | 仅 `/api/pick` 跨进程传路径，已统一 UTF-8；勿改 helper 编码 |
| 去词失败 | 确认是 mp4；命中时间戳异常时增/减缓冲；原文件已备份可恢复 |
